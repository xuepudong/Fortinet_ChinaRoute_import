# 更新日志

## v1.1.0 - 2026-08-27

### 修复
- **修复资源不足时部分地址无法加入组的问题**
  - 之前当 FortiGate 资源不足导致部分地址创建失败时，脚本仍会尝试将所有地址（包括失败的）加入地址组
  - 这会导致近 1000 个不存在的地址对象无法正确加入 `Group_ALL-CN`

- **修复大地址组更新超时问题**
  - 更新 8000+ 条记录的地址组时频繁出现 `ReadTimeoutError` 超时
  - **根本原因**：批次太大（1000条）+ 超时太短（30秒），FortiGate 处理大 JSON 负载需要更长时间
  - **解决方案**：
    - 批次大小从 1000 降至 300
    - 超时时间动态调整：第1批60秒，后续批次递增（60s → 70s → 80s...）
    - 增加超时重试机制（每批最多重试2次）
    - 批次间增加2秒延迟，让 FortiGate 有处理时间

### 新增
- **智能重试机制**
  - 单个地址创建失败时自动检测超时和资源不足错误
  - 检测到资源相关错误后等待 0.5 秒自动重试
  - 批量创建完成后，所有失败的地址会在 5 秒后以更低并发（原并发的 1/2，最少 5）统一重试

- **精确追踪成功地址**
  - 实时追踪哪些地址成功创建
  - 只将成功创建的地址加入地址组
  - 避免引用不存在的地址对象

### 改进
- 更详细的日志输出
  - 显示批次更新进度（批次 X/Y）
  - 显示每批的超时时间和重试状态
  - 区分首次创建和重试的统计数据
- 优化并发控制
  - 重试时自动降低并发以减轻 FortiGate 压力
- 超时策略优化
  - GET 操作超时从 10 秒增加到 60 秒
  - PUT 操作超时动态调整（60-120+ 秒）

### 技术细节
修改的核心方法：
- `create_address()`: 增加 `retry_on_timeout` 参数，支持超时自动重试
- `batch_create_addresses()`: 返回 `(created, failed, successful_names)` 三元组
- `update_group_members()`: 批次大小 1000→300，超时动态调整，增加重试和批次间延迟
- `update_single_isp()`: 只使用 `successful_names` 更新地址组

## v1.0.0 - 2026-08-26

### 初始版本
- 支持自动更新中国大陆全部 IP 到 FortiGate `Group_ALL-CN` 地址组
- 支持 Docker 多架构部署（amd64/arm64）
- 支持定时自动更新
- 企业微信通知集成
